## 2024-03-19 - Cloudflare Worker Environment Caching Anti-Pattern
**Learning:** In Cloudflare Workers using the ES module syntax, the `env` object passed to the `fetch` handler is re-instantiated for every request. Attempting to use strict object equality (`env === cachedEnv`) as a cache key for module-level optimizations completely fails because the reference changes. Furthermore, returning a globally cached array (like authentication keys) directly introduces severe security risks because a downstream consumer could mutate the cached list (e.g. `array.push()`).
**Action:** Always cache on the *raw string values* of the environment variables (e.g., `env.WORKER_AUTH_KEYS === cachedStr`) rather than the `env` object itself. Additionally, always return a shallow copy (e.g. `[...cachedArray]`) when returning arrays from module-level caches to prevent accidental mutation of the shared state.
